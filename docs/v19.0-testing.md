# ProcessWire 19.0 testing

## Scope and source decision

Debian 13 Trixie does not package ProcessWire. The appliance therefore uses
the official ProcessWire 3.0.258 source archive at commit
`6b28a805c07d3b0509b53ce6632c03834fe38964`. The build verifies its SHA-256
as `c073b4c44dcce711883cfa73b2d5b079f3547c9d810ab88f4ca657bb3d53adaf`.
The official beginner site profile is pinned at commit
`4e6cfd1f16c6aa926effaebd6bab25a44367d2bd` with SHA-256
`99b850c2d3db949e75ca014cd85cca66d35dfab2bcca415bf702ecd567e6733f`.

ProcessWire identifies the 3.0 main branch as stable, published 3.0.258 through
its official Composer package on 14 August 2026, documents PHP 8 support, and
maintains a security guide and issue-reporting route. PHP 8.4, Apache,
MariaDB, Postfix, and the required PHP extensions come from signed Debian
Trixie repositories.

ProcessWire's supported core update procedure replaces the `/wire` directory
while preserving the site directory and database. `processwire-update --check`
queries the official stable metadata without changing the installation. A
supervised update accepts a stable version and independently obtained SHA-256,
verifies that metadata resolves to the official ProcessWire GitHub repository,
backs up the database and current core, then applies that documented core
replacement.

## Known limitations

Docker runtime validation does not exercise the installer, kernel, bootloader,
or physical hardware. ProcessWire adds no appliance-specific behavior at those
boundaries, so the validated Core 19 baseline supplies inherited evidence.

The page round trip uses ProcessWire's page API after separately proving the
real administrator HTTP login. It avoids browser-only editor behavior while
exercising the same template, fields, database, and public rendering layers.

The acceptance test checks the update channel without applying an update to
the accepted site. Core updates are supervised because administrators must
back up and check site module compatibility before replacing the core.
